# Railway Core Pass — Issues #8 / #9

Base: `main` / `99217aa`. Railway uses independent TrackNode / TrackSegment IDs and adjacency. The Road Graph, traffic, transit and Map Asset schema stay independent. Pure curve/metric geometry and the common LandOwnership construction footprint API are reused.

## Phase 1 — infrastructure

`RailwayInfrastructure` is owned by SimulationState in the Simulation Worker. `build-track`, `place-station`, `place-depot`, `set-rail-switch` and `remove-railway` are commands, never renderer writes. Endpoints snap to Track segments; intersections split them and produce logical Junctions. Switch pairs constrain connectivity. Standard/narrow track types specify metre gauge, km/h limit, minimum radius, 4% surface grade and electrification placeholder.

All four construction modes are available from the Railway panel. Click start, direction control(s), end; Esc cancels, Backspace steps back. Continuous mode retains the circular-arc construction geometry and carries the previous endpoint/tangent into the next arc; each arc remains an independent Track segment. Long straight legs are checked/sampled every 4m so tracks follow authoritative ground and reject hidden steep slopes/water. Paths exceeding 16,384 geometry samples must be built in shorter sections; this is a per-construction budget, not a World size limit.

Station placement snaps to a straight existing Track with 80m approaches and 20–400m platform length. Single (1 platform / 1 track), double (2 / 2), island (1 / 2) templates create Track sections, PlatformFace IDs, physical platform outlines and Junctions for the additional track. Each face records associated Track, offset, side and direction. `fitsPlatform(faceId, metres)` is the Formation length API. Depots have connected Track, capacity and a physical footprint. Remove stations/depots before deleting their referenced Track.

Track, Junction and PlatformFace are exclusive logical Block resources. Occupancy/reservation owner and atomic conflict checks are foundations for route requests. This deliberately conservative model is not detailed signaling or interlocking. Occupied/reserved infrastructure cannot be edited or undone. Railway construction shares the existing global Undo/Redo history; failed Undo/Redo keeps its history entry.

Save v13 gains optional additive `railway` version 1; missing means an empty railway. Full graph/station/platform/depot/block state is saved. Load validates detached components before replacing live state; malformed references/geometry/IDs reject the load. Infrastructure is protected from terrain brushes alongside existing road terrain protection. Renderer samples the authoritative Terrain and queries a Track grid index only when the camera crosses a 128m cell or view radius bucket. Only local Track/platform/depot representations are created; snapshots do not add heightmap copies. Network revision is separate from resource/runtime revision.

Phase 1 verification: `npm test` 306 tests / 40 files and Production Build passed, including 12 infrastructure regressions: independent/snap/switch graph, all curve modes, templates/faces/length/depot, atomic reservation conflict, sampled terrain/curve/water/owned land validation, shared Undo/Redo/terrain protection, legacy/corrupt saves.

## Phase 2 — operations

`RailwaySystem` extends the infrastructure Authority with distinct RailLine / ServiceType / TrainService / StopCall / FormationType / Formation / Operation models. Calls and events use absolute integer GameClock seconds, including day boundaries. Turnback connects different service IDs in an ordered Operation with one Formation and at least 20 seconds between services. Deadhead is an ordinary `passengerService=false` service; it does not board OD groups.

Dijkstra routing respects gauge, selected switch pairs and face direction. Route samples have section-specific speed limits. A stable binary event heap handles activation, dwell-complete, departure, route-request and arrival. Due-event work is bounded to 1,000 events per tick; overdue events preserve event-time ordering. Resource-indexed waits wake on release instead of polling every waiting train. Nothing runs while paused. `railwayEventMs` is added to the existing performance ledger.

Reservations are deliberately conservative: the entire service itinerary (tracks, junctions, faces) is atomically reserved before originating and retained until the terminating dwell completes. This prevents opposing trains from occupying intermediate stops and deadlocking a single-track service. Following trains and overlapping platform use wait. At a turnback only the terminal face/track is retained until the next service reserves its route. Busy infrastructure and timetables are frozen until **STOP AND CLEAR TIMETABLE**, including infrastructure Undo/Redo. This prototype prioritizes exclusivity; it has lower throughput than realistic signaling or dispatching and arbitrary conflicting multi-line turnback schedules may require timetable changes. Depots limit the formation pool; originating/finished operations use abstract depot staging rather than detailed access/shunting movements. Explicit deadhead services still follow their full timetable and Track route.

Frequency input supplies line/type, ordered faces with stop/pass choice, first departure, service window, headway, FormationType, depot and return service. It expands into the same individual data accepted by `set-rail-timetable`; no second frequency Simulation or OuDia format is introduced. Creation validates assignment uniqueness, timing, operation continuity, gauge, route, platform length and depot capacity. Definitions are bounded to 5,000 services / 50,000 calls / 512 formations; routes are cached by face pair/type. OD group commands provide aggregate boarding/alighting and leave capacity overflow waiting; existing Individual Citizen / bus transit state is independent.

The Railway panel lists lines, service/train number, calls and actual times, face, delay, Formation, Operation, active trains and occupied/reserved resources. Dwell can be extended to exercise delay propagation. Physical minimum travel, blocked departure and extended dwell delay propagate into subsequent calls and services.

Snapshots contain static infrastructure/timetable definitions plus separate runtime data. Between events Worker messages carry **runtime only**, without graph or Terrain buffers. Renderer advances the existing visual GameClock, interpolates active legs and queries cumulative path samples with binary search. Only camera-local active formations become car meshes; future/depot formations are never meshed. Node/junction crosses, station boundaries, face markers and occupied/reserved track colors provide debug views. World replacement disposes both railway and train meshes.

Save v13's optional railway payload now includes operations version 1: definitions, formation states, actual calls/delays, event heap, resource waits, active legs, OD groups and counters. Detached load validates IDs, assignments, routes, resource ownership and clock agreement before changing the live city. Existing saves without railway continue to load empty infrastructure. Construction suitability is validated at build time; later water-level/terrain changes do not prevent existing infrastructure from loading. No Map Asset schema change is introduced.

Verification covers deterministic Save resumes during dwell, running, blocked reservation and turnback; opposing/following train waits; pass; separate return service IDs; deadhead; capacity overflow; physical lateness/dwell extension; invalid assignment/gauge/platform/timing; Pause/x1/x2/x4/x8; Worker runtime-only updates; camera culling/world replacement; continuous construction/cancellation. Production-browser smoke used a new flat 1km city, built an island station, single station and depot with UI clicks, generated 60 services / 3 formations / 3 operations, observed departure/arrival/turnback and wait delays at all speeds, and saved/reloaded an active train. Console warnings/errors: none. WebGPU remained near 58–60 FPS on this small scene; this is a smoke observation, not a dense-network benchmark.
